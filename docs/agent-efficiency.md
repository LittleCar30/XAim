# 第一阶段：减少 Agent 执行开销

2026-10-11。目标是减少文件读取的模型往返和只读步骤的磁盘开销，同时保留真实写入的版本保护、检查与中断保存。

## 批量读取

原生工具新增 `read_files`，接受 1 至 8 个路径。单次返回各文件正文、完整版本 hash、`next_offset` 与 `complete`；总输出不超过 24000 字符，包含 JSON 转义和元数据。长文件可用 `read_file` 从返回位置继续读取。

每个文件使用相同的路径、敏感文件、链接和 1 MB UTF-8 文件限制。单项失败返回错误，其他项目继续。批量返回值中的成功文件计入实际读取记录；全部失败不构成零变更编码任务的完成依据。实时与历史上下文统一解析成功片段。

批量读取减少已知多个路径时的工具请求需求，模型可以在一个回合取得多份源码；是否选择该工具及在线收益仍取决于实际模型。

## 轻量状态持久化

原来每个模型回合和工具结果都扫描任务副本、重建文件差异，并重新写入阶段性候选。现在读取、搜索、状态提交和验证结果更新只保存任务元数据，保留最后一次实际写入的候选。

任务初始化、成功修改、最终报告和异常退出仍扫描并保存实际文件差异。没有内容变化的编辑仍校验当前 hash 和唯一匹配，但不写文件、不递增修订号、不使同一任务的已有验证结果失效。实际修改仍清除已验证修订并重新检查。

验证复用沿用当前任务修订规则，不是跨任务、跨工具链或跨依赖环境的持久缓存。外部环境变化的完整有效性指纹仍需后续实现。

## 可测量的执行成本

SQLite 诊断增加以下数据，不记录密钥或额外源码正文：

| 诊断 | 字段与含义 |
| --- | --- |
| `workspacePreparation` | 初始源码副本的准备时间、文件数、字节数 |
| `verificationPreparation` | 检查环境准备总时间、源码复制时间/数量、Node 依赖复制时间/条目/字节、Node 与 Python 复用原因 |
| `checkpointPersistence` | 元数据或完整文件保存方式、修订号、保存耗时 |
| `verificationReused` | 复用的任务修订与检查数 |

Node 条目数包括目录，字节数为复制文件的逻辑字节；复制失败时可能为部分计数。源码统计来自实际快照基线。耗时使用单调时钟，毫秒可能为零。`run_verify` 工具耗时改为实际调用耗时，缓存命中不再重复计入旧结果的检查时间。

上述准备时间和原有模型响应、工具、验证执行时间有包含关系，不能直接全部相加。初始源码准备不包含随后继承待应用文件的成本。

## 回归范围

覆盖批量读取的转义输出上限、Unicode 分块续读、hash 编辑、敏感/越界拒绝、部分失败、零变更完成依据、实时/历史上下文、只读步骤不重复完整保存、无变化编辑的检查复用、真实编辑重新检查，以及后续模型失败时保存候选。

核心集成回归使用真实 Node 项目检查：先检查原值，再做无变化编辑并复用检查，随后改值并重新检查，最终审阅应用。验证期间原项目保持基线版本。

该回归的 7 次模型响应共执行 6 个工具调用，完整候选持久化仅发生 3 次：初始化、真实写入、最终报告；项目检查实际运行 2 次，无变化编辑后的请求及最终提交均复用已有结果。

本地验收：Rust 库 638 项通过、2 项按原配置忽略；评测运行器 14 项通过；前端 147 项通过；React → Rust → Diff → 应用 → 实际项目检查 E2E 1 项通过。TypeScript、ESLint、rustfmt 和差异空白检查通过；Clippy 通过，保留现有 `index/watcher.rs` 的 while-let 建议。模型请求使用本地模拟服务，不产生在线 API 费用；E2E 不覆盖原生桌面窗口。

在线模型未做本轮对照评测，不声明任务成功率或端到端速度提升比例。批量读取、轻量持久化和诊断适用于原生工具循环；兼容补丁执行路径未迁移。
