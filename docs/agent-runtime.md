# Agent 执行内核

原生工具交互优先请求流式响应，正文逐段显示并保存到任务历史；工具参数按索引完整拼接，响应正常结束后才执行。
端点明确拒绝流式时回退非流式，并在当前 provider 实例内记住兼容结果；仅不支持 usage 选项时继续流式但用量标记未知。
端点忽略流式、返回 JSON 时接受同一响应，不重复请求。断流、取消或时限耗尽时保留已完成变更与中断正文，不执行残缺工具，也不自动重放该响应。
非工具兼容补丁流程、连接检查及结构化规划仍保留非流式接口；流式不保证消除网络或网关故障。

## 执行内核

任务在临时源码副本中读取、搜索、创建和编辑文件，包含当前工作区的未提交与未跟踪源码。
已有文件编辑需要读取版本的 hash、非空且唯一的匹配文本；文件路径不得越界或指向链接、Git 元数据和敏感文件。
程序根据任务前后内容生成逐文件 Diff，不要求模型生成补丁或默认生成三个候选。

模型提出完成后，程序执行最终检查。检查失败会回到模型修复，最多三轮；源码未变化却重复提交相同失败时停止。检查无法运行时明确记录为无法验证。
已有文件满足要求时，模型须成功读取并核对内容，可以零变更完成任务；程序仍执行最终检查，任务直接结束，不生成补丁或等待应用。
介绍、分析、解释、审查等只读任务可直接回答，零变更正常结束，不要求生成补丁或运行代码检查。包含修复或实现要求的任务仍按编码任务处理；发生文件写入时仍执行验证流程。
编码任务既无文件变更也无成功读取记录的完成声明会收到一次纠正提示，再次无依据声明完成则停止。完成状态不代表无法运行的检查已通过。
输入框的“运行项目检查”仅授权本次任务。默认不执行仓库脚本；授权后只运行自动检测的检查命令，
“运行开发命令”另行授权本轮的 `run_command`、`clone_repository`、`start_process`，不由项目文件或模型参数授权。`read_process`、`stop_process` 仅能操作本项目由应用启动的进程。日志记录命令、工作目录、结果、用量及每轮响应的结束原因和耗时；思考内容仅按协议回传，不展示或保存到历史。
项目脚本仍以当前用户权限运行，隔离副本不是操作系统沙箱，也不限制其网络或其他文件访问。

任务默认最多 32 次模型响应、96 次工具调用、500000 总 token，工具循环最长 30 分钟。
输出预算按已知模型能力设置，未知模型使用保守值；用户显式额度是硬上限。
上下文预检复用上一轮服务端报告的提示 token 数，并对新增消息做保守估算；缺失用量时按预留额度计入任务预算。
截断响应在执行工具前整轮丢弃，预算允许时重试一次，不重复执行已完成的编辑。
长文件按 offset 分段读取，工具输出有长度限制。历史读取与搜索结果会裁剪；支持检查点的模型适配器在上下文或累计预算紧张时，
使用程序维护的结构化状态重建上下文，不增加摘要模型调用，并保留最新完整工具调用组。
检查点区分真实工具操作与模型声明，保留目标、待办、文件版本和验证结果。预算收尾仅允许检查和真实检查失败后的必要修复；
中断或预算耗尽时保存阶段性 Diff 和报告供审阅，不自动应用，也不代表任务完成。可以基于这些成果发起下一轮，尚不支持从中断的工具调用位置恢复执行。

已知多个文件路径时，可用 `read_files` 一次读取最多 8 个文件，返回各文件正文、版本 hash 和继续读取位置；总输出限制为 24000 字符，单项失败不阻止其他文件读取。实时与历史上下文均展示成功读取的片段。
读取、搜索和模型回合只持久化任务状态，不重复扫描源码或写入完整 Diff；实际写入、任务初始化、最终交付和异常退出仍刷新文件差异。相同内容的编辑不增加源码修订，不使本次任务已有检查失效；实际修改仍触发重新检查。
诊断记录新增工作区准备、检查环境准备、源码与 Node 依赖复制量/耗时、依赖复用原因、检查复用和检查点保存耗时。检查工具耗时记录实际调用时间，不重复累计复用结果中原检查的耗时。实现和验证边界见 [执行效率改进](agent-efficiency.md)。

## 多轮会话与文件审阅

任务结束、失败、受阻或等待应用时均可继续输入；侧栏按会话分组，同一会话保留各轮的用户请求、回答、执行记录和补丁。重新打开历史会话也可继续。受阻任务不提供应用入口，阶段性编辑可带入下一轮。
实时回复与历史回复统一支持 Markdown 标题、列表、表格、引用和代码块；复制输出保留原始 Markdown。原始 HTML 不执行，图片仅显示描述。
设置按模型与连接、任务与检查、项目索引、安全与确认、界面与外观、数据与存储分类；切换分类保留未保存内容。输入框的问号按钮可查看“运行项目检查”的授权范围。
每次执行仍使用独立任务编号。会话关联和历史保存到 SQLite，重启后可恢复；发送下一轮时带入最近最多 24 轮、48000 字符的公开请求与回答，超限裁剪旧轮次。原始工具协议和隐藏思考不重放，必要文件可重新读取。
未应用的文件变更会带入下一轮隔离副本，成功后由新结果接替旧待审阅结果；下一轮失败时保留上一轮的应用入口。
一次任务可创建或修改多个文件，非工具兼容流程也将同一响应的多个文件作为完整候选评估。待应用的新文件显示在文件树，可预览生成版本；点击应用后才写入原项目，并刷新文件树。

原生工具循环自动加载任务副本中的项目约定：每个目录依次选择首个非空 `AGENTS.override.md`、`AGENTS.md` 或 `CLAUDE.md`。
约定仅作用于所在目录及子目录，更深目录覆盖父目录；用户要求及程序权限、验证和预算规则优先。不会加载宿主机的全局约定。
单文件最多 8 KiB，项目总计最多 32 KiB（含来源元数据）、128 个来源；超限或编码错误会提示并省略整份规则，不拼接残缺规则。
约定以任务开始时内容为准，来源显示在执行时间线；完整作用范围和省略原因记录在诊断事件中。

模型可调用 `search_symbols` 和 `read_symbol`，利用 Tree-sitter 查找和读取 TS/JS/Python/Rust/Go/Java 的声明。
符号缓存独立于原项目的 SQLite 索引，每次请求依据副本文件 hash 更新；返回的完整文件 hash 可用于编辑。
搜索最多返回 50 条结果、扫描 32 MiB 支持的源码，超限会标明检索不完整，可用 `path` 缩小范围；长声明支持分块读取。

确认仅应用任务产生的文件变更，不自动初始化仓库、Git commit、reset 或清理用户文件。
应用与撤销均比较文件完整版本；用户随后修改过相关文件时拒绝覆盖。新任务的基线和执行事件持久化到 SQLite。
旧任务没有文件基线时需要重新运行，不能直接应用或撤销。

当前限制：源码副本不复制 `node_modules`、`target`、虚拟环境、构建输出、敏感文件或链接；
检查在独立验证副本中执行，生成物不会进入候选补丁，文件副作用会记录。依赖清单/锁文件未变化时复用项目已安装的 Node 依赖副本和 Python 虚拟环境解释器；
依赖缺失、清单变化或依赖副本超过限制时报告无法验证；授权开发命令后，模型可以显式安装任务副本依赖，最终检查优先使用该依赖环境。已有 Cargo.lock 的默认检查使用 --locked。
Node 优先使用项目 typecheck/lint 脚本，否则直接调用本地工具；Python 根据配置与测试 imports 选择 python -m pytest 或 unittest。
快照最多 50000 文件、单文件 32 MB、总计 256 MB；Node 依赖副本另限 50000 项、256 MB、128 层，不复用指向项目外的依赖链接。
文件工具支持不超过 1 MB 的 UTF-8 文本。尚未提供从工具中断位置恢复、原生 Anthropic 接入、OS 沙箱或多代理。

## 操作执行与验收

`run_command` 接收 `program`、`args`、任务副本内的 `cwd` 和可选时限，实际记录退出码、输出及耗时；取消与超时终止进程树。默认 300 秒，最长 3600 秒，并受任务总时限约束。命令引起的源码变化使已有检查失效。依赖清单一致时可复制原项目 Node 依赖，模型显式安装的依赖优先使用。

`clone_repository` 先在同一文件系统暂存并核对 origin、HEAD 或空仓库、子模块及 LFS，再以不覆盖已有目标的方式交付完整仓库。克隆成果作为新的源码基线，不转换为文本 Diff。交付后再次核对仓库；源码副本准备失败时仍保留已交付证据，并报告异常。取消不会撤销已经交付的目录。

对可识别的克隆、安装、测试、构建和启动请求，程序分别要求匹配的实际工具结果；组合任务要求全部满足，后续同类失败使早先的成功失效。启动工具本身不算完成，必须读取输出并在提交时仍存活；服务业务就绪及具体行为仍需模型按用户要求检查。完成判定不能代替对用户全部语义要求的验收。

`report_blocked` 保存具体原因、未完成事项、操作证据和阶段性编辑，终止为 `blocked`，`completionConfirmed` 为 false。缺少命令授权的明确操作任务在模型调用前即受阻；生成替代脚本不能满足该操作目标。支持范围、使用示例与限制见 [开发操作](development-operations.md)。
