# 会话、上下文与分析任务修复说明

XAim 是 Tauri 2 + Rust + React 的桌面编程 Agent。React 负责会话、文件树、变更审阅和配置；Rust 负责模型请求、文件检索与受控编辑、任务编排、验证和 SQLite 持久化。

主要路径是：用户输入 → 建立任务与源码基线 → 模型工具循环 → 程序汇总实际文件差异 → 验证 → 用户审阅并应用。文件操作先发生在隔离源码副本中，原项目在应用之前不会被改写。

## 四类问题的原因与修复

| 现象 | 原因 | 本次行为 |
| --- | --- | --- |
| 输出后不能继续同一对话 | 输入栏把待确认状态视为运行中；历史视图没有输入栏；发送时创建独立任务且重置展示 | 待确认、已完成和失败后均可续聊；历史视图保留输入；一个会话关联多次执行并展示各轮 |
| 每次看起来没有上下文 | 已有任务记录、检索和执行内检查点，但没有跨任务会话关联，也没有把历史公开回答带入新执行 | 保存 conversation_id / parent_task_id；从 SQLite 恢复公开问题与回答，重启后可续聊；读取过的文件片段显示在上下文面板 |
| 好像一次只能生成一个文件 | 原生工具循环本身支持多文件；兼容补丁流程把同一响应的文件拆成候选，然后只选择一个；文件树也没有及时刷新 | 同一响应的多文件作为完整候选评估和保存；一次应用完整变更；待应用新文件可见并可预览，应用后刷新树 |
| “介绍项目”读完文件却失败：任务未产生代码变更 | 旧运行版本把完成与存在补丁绑定，纯分析不满足写文件条件；这不是实际文件内容冲突 | 介绍、解释、分析、审查以公开回答作为成果，可零变更成功结束；不要求伪造补丁，也不执行无关代码检查 |

用户提供的失败记录中，读取工具正常完成，最后提交任务状态后出现“任务未产生代码变更”，因此失败发生在成果判断阶段。当前源码原本已有读取现有文件后零变更完成的部分支持，但还不足以稳定处理详细分析、直接回答和历史追问。本次同时完善了回答长度、任务类型判断和结束条件。

现场检查发现仍在运行旧安装版本；修改源码和重新构建不会更新已运行进程。需要退出旧实例，再启动新构建版本。

## 上下文与待应用变更

历史永久保存和模型当前上下文是两件事。数据库保留执行记录；每轮模型请求只恢复最近最多 24 轮、48000 字符的公开问题与最终回答，超限丢弃最早轮次。不会重放隐藏思考或旧工具调用协议，文件内容按需要重新读取。长执行仍使用现有程序检查点和预算管理。

待应用的变更会叠加到下一轮隔离副本中，新一轮结果包含完整待应用文件集。新执行成功后接替上一轮待审阅结果；新执行失败时保留上一轮审阅入口。前置历史加载失败也不会把上一轮误标为失败。

模型明确报告仍有待办时，单独输出一段正文不会清空待办并提前结束。纯分析任务可直接回答；请求同时包含修复、实现等操作时默认按编码任务处理，实际写入会继续触发最终验证。

文件树中的“待应用”表示文件已生成并保存，但原项目尚未写入。预览从任务保存的文件版本读取；应用和撤销仍核对完整文件基线，避免覆盖用户后续修改。

## 与 Codex、Claude Code 的对比

以下比较针对会话和编码工作流，不代表所有客户端版本和权限配置完全相同。

| 能力 | 修复前 XAim | 修复后 XAim | Codex / Claude Code |
| --- | --- | --- | --- |
| 连续对话 | 独立执行为主，历史主要用于查看 | 同一会话多轮执行，可打开历史继续 | 支持持续会话和后续追问 |
| 会话上下文 | 执行内工具上下文、检查点；缺少跨轮关联 | 持久历史 + 有界恢复公开问题与回答 | 支持会话历史、上下文管理和恢复；具体策略由产品决定 |
| 项目约定 | 已加载 AGENTS.md / CLAUDE.md 等目录规则 | 保留现有能力 | 支持项目指令文件；各自规则与作用范围不同 |
| 多文件工作 | 工具模式支持；兼容候选选择可能丢文件 | 两种路径均保留整体多文件结果 | 支持多文件读取、编辑和任务执行 |
| 无代码的成果 | 部分零变更任务可完成，纯分析容易被误判 | 分析回答本身就是成果 | 可解释、分析和审查，无需一定写文件 |
| 写入时机 | 隔离副本 → 手动应用 | 保留隔离审阅，并提供应用前预览 | 可在选定工作区或 worktree 中执行；写入和审批行为依配置而变 |
| 中断恢复 | 保存阶段性成果 | 可基于失败成果开始新一轮；不能恢复到某个中断工具内部 | 提供会话继续/恢复能力；不等于任意工具内部事务均可恢复 |

XAim 现在补齐了这些会话与成果处理的基础能力，仍有边界：没有原生 Anthropic 适配器、操作系统级沙箱或多代理；模型恢复的是有界公开历史，并非整个会话所有文件和工具输出。模型真实表现还取决于所配置服务的工具协议、输出额度和网络稳定性。

参考：[Codex CLI](https://learn.chatgpt.com/docs/codex/cli)、[Claude Code 工作方式](https://code.claude.com/docs/en/how-claude-code-works)。

## 验证范围

回归覆盖分析零变更完成和长回答、明确待办不被正文清空、数据库升级与重开后续聊、待应用文件继承、续聊失败保留旧审阅、多文件候选整体应用/撤销、历史上下文和应用前文件预览。

前后端单元测试及真实 Rust 后端集成流程使用模拟模型，不产生真实 API 费用。浏览器预览用于检查界面布局和操作，不能代替真实模型或 WebView2 原生 IPC 的完整验收。
