# Windows 发送任务闪退分析（2026-10-10）

## 证据与原因

用户安装的 `D:\XAim\xaim.exe` 在 2026-10-09 23:59:38 和 2026-10-10 00:03:58
均产生 Windows Application Error 1000。异常代码 `0xc00000fd` 表示线程栈溢出；
相同故障偏移 `0xfaa707` 通过旧包构建时保留的发布版 PDB 解析为 `__chkstk + 55`，即 Windows 栈探测函数。

对旧安装版启动临时 WebView 调试端口后，直接调用真实 Tauri `run_task`，
使用项目 ID `-1`、验证授权 `false`。该调用在创建任务和发出 API 请求之前就再次退出，
Application Error 的异常和偏移均相同。因此本次故障发生在桌面任务入口，
不由 API 网络、模型响应或 SSE 数据内容触发。

任务入口直接内嵌整个编排器 future；编排器又内嵌原生工具和兼容补丁的执行状态。
调试构建实测 `Orchestrator::run_task` 的 future 为 59,736 字节，命令业务层 `run` 为 60,616 字节。
这些状态在创建和搬移过程中会形成临时值，继续放大 Tauri IPC 调度调用链的栈需求。
真实桌面入口复现与修改后的对照验证用于判定原因；仅测量 future 字节数不能计算精确峰值栈用量。

评测二进制显式使用 8 MiB 线程栈，Rust 常规测试也没有经过桌面窗口的 IPC 创建路径。
现有 React 集成测试替换了原生 IPC，通过 Rust 测试进程调用命令业务层，因此未覆盖此故障点。

## 修复

- 在 Tauri 命令到业务执行、业务执行到编排器、编排器到执行流程、原生工具流程到工具循环处使用 `Box::pin`。
- 大型异步状态分层放到堆中，缩小调用方状态；保持原有 await、取消、错误和流式行为。
- 不通过改 API、退回非流式或增大桌面线程栈规避故障。

修改后同一调试构建测得编排器入口为 296 字节，命令业务层为 888 字节。

## 回归方式

- 入口 future 大小上限 8 KiB；该检查在修改前实测失败。
- 原生工具及兼容补丁流程分别在显式 1 MiB 线程栈上执行至等待确认，原生流程再确认应用。
- `scripts/check-desktop-ipc.mjs` 经真实 Windows WebView 调用 Tauri 命令，连续三次拒绝不存在的项目，
  再确认 `list_providers` 正常返回。该脚本不会发出模型请求或改动用户数据。
- 完整 Rust 库测试、React 到本地 SSE 工具工作流，以及最终发布版安装包构建。

真实 IPC 探针只覆盖此次发送入口和错误返回；完整任务的协议、编辑、取消、验证与应用继续由独立测试覆盖。
本次修复不代表 API 网络故障、验证环境准备或操作系统沙箱等既有问题已解决。
