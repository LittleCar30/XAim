# 开发操作

原生工具模型可以真实执行开发操作。输入栏的“项目执行权限”默认按需询问，统一管理检查与开发操作；执行前展示程序生成的命令、位置、网络与影响。允许本轮只批准相同范围的操作，按项目记住会保存明确范围，并自动切换为按项目授权模式。缺少授权或能力会显示“受阻”及具体待办，不把生成脚本算作完成。

| 工具 | 用途与交付 |
| --- | --- |
| `clone_repository` | 克隆公开、无内嵌凭据的 HTTPS Git 仓库，完整保留 `.git`、工作文件与二进制 |
| `run_command` | 运行已支持的开发程序，返回真实退出码、输出与耗时 |
| `start_process` | 启动服务并返回进程 ID，需继续读取输出、核对状态和实际地址 |
| `read_process` / `stop_process` | 读取、停止本项目由 XAim 启动的进程 |
| `report_blocked` | 保存原因、待办及阶段性编辑，并结束本轮 |

## 使用

打开空项目目录，输入“把 https://github.com/组织/仓库 克隆到当前目录”。批准克隆提示后执行。目标 `.` 要求原项目为空；非空项目可指定尚不存在的子目录，其父目录须已存在。已存在目标不会被替换。子模块可指定递归克隆，LFS 内容会实际拉取并核对。完成后刷新文件树；克隆成果已在原项目，不需要应用 Diff。

安装、测试或构建可输入“安装依赖并运行测试”，或者给出具体程序及参数。Node 依赖装在任务副本；Python 使用 `python -m venv .venv` 后通过 `.venv/Scripts/python.exe`（Windows）或 `.venv/bin/python`（macOS/Linux）调用 pip。程序不进行全局 npm 安装或通过系统 Python 安装 pip 依赖。

启动服务后，执行记录提供进程 ID、输出和状态。模型应核对服务地址及业务就绪。后续对话可要求停止该进程。失败、受阻、取消的任务会停止本轮新启动的服务；成功任务的服务最长运行一小时，退出应用或超时会停止，应用重启后不恢复进程。

## 网络与授权恢复

项目执行权限入口提供 Git 网络设置：系统代理 / 环境配置（默认）、直连、自定义代理。Windows 读取当前用户启用的静态系统代理；macOS 读取静态 HTTP/HTTPS 系统代理；Linux 使用环境及 Git 配置。系统模式保留已有 Git 和环境代理，暂不解析 PAC。显式代理不支持内嵌账号密码，仅传给仓库下载进程，不改写全局 Git 配置。

连接错误明确提示检查 Git 网络设置。受阻或失败后可修改设置，点击“重试本次任务”发起同目标的新一轮，保留上一轮记录。授权等待是在当前任务中继续，不重新调用模型或重做已完成编辑；取消不会执行待授权操作。重启后不会恢复或批准旧请求。详见 [项目执行权限](execution-permissions.md)。

## 范围与限制

- 支持程序包括 Git 查询、Node/npm/npx/pnpm/yarn、Cargo/Rust、Go、Python/pytest、make、tsc、eslint，以及运行项目脚本的 PowerShell/bash/sh。程序必须已安装；shell 不接受命令串或 `-c`。
- 未安装的程序、不存在的项目脚本、已达上限的开发进程，以及未接入的工具或命令，会以“环境不可用/不支持的操作”返回模型，由模型改用其他方式或如实报告受阻，不直接终止任务；缺少执行授权、写全局环境等策略性拒绝仍直接受阻。
- Windows 可执行文件格式或架构不兼容（错误 193/216）同样返回模型恢复，保留原始系统错误供诊断；不把这类环境问题当作权限拒绝。
- Git 写操作目前只提供专用克隆。commit、reset、push 等没有接入；私有仓库认证、SSH URL 和交互输入尚不支持。
- 命令、安装和服务以当前用户系统权限执行，工作目录与程序限制不是 OS 沙箱；项目脚本仍可访问其他文件及网络。
- 命令在任务源码副本运行，文本源码变化仍需审阅；依赖和构建输出不进入补丁，依赖保留在该任务工作区。下一轮新建副本时需要重新准备依赖。清单一致时可复制原项目的 Node 依赖；自动检查可复用原项目 Python 虚拟环境。
- 输出保留最近 24000 字节，命令默认 300 秒、最长一小时且受本轮总时限约束。明显的密钥模式会脱敏，不能保证任意脚本输出都不含敏感信息。
- 完成判定依赖实际结果，检查不能完全证明业务正确。没有原生工具支持的模型兼容流程不具备这些新操作能力。
- 完整克隆直接交付，不受文本补丁撤销管理；已交付后发生取消或后续失败时，仓库保留，报告记录交付事实与剩余待办。
