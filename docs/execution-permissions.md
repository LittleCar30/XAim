# 项目执行权限

对话输入栏的统一入口替代“运行项目检查”和“运行开发命令”两个本轮开关。

| 模式 | 行为 |
| --- | --- |
| 只分析（不运行程序） | 读取、分析、生成候选修改；不会运行测试、构建、安装或服务 |
| 确认后执行（默认） | 每个新操作展示真实程序、参数、目录、网络和影响，用户批准后继续 |
| 自动执行已批准操作 | 已批准过的相同操作自动执行，参数、目录、脚本、可执行文件或网络设置变化仍询问 |

执行提示包含命令与参数、任务副本/原项目位置、网络需求或可能性及影响。“这次允许”只批准这一范围；“以后允许相同操作”保存相同范围并切换为自动执行。用户可在入口查看与撤销保存的操作。授权等待期间不再请求模型；拒绝会结束当前任务，不运行待授权操作。

范围身份包含工具类别、规范化相对目录、完整参数、解析后的可执行文件指纹以及相关项目清单、锁文件、包管理器脚本直接引用的文件内容指纹。启动服务与一次性命令为不同范围；克隆还包含仓库地址、交付位置、递归子模块设置和 Git 网络配置。授权不覆盖所有同名程序，不接受来自模型的通配授权或项目文件中的信任声明。用户选择与范围保存在本机数据库，重启保留；待处理请求不恢复，重复、错任务和过期响应被拒绝。启动前会重新计算 scope，授权等待期间文件或可执行文件发生变化会重新询问。

这是程序的执行审批机制，不是操作系统沙箱。脚本以当前用户权限运行，仍可能访问其他文件与网络。候选修改仍需单独审阅，克隆完整目录直接交付；停止已启动服务不要求再次批准启动权限。需要隔离不可信代码时，应在外部容器或 OS 沙箱中运行 XAim。

递归子模块会先下载顶层子模块，再检查所有已出现的 `.gitmodules`；只允许不含凭据的 HTTPS 地址，禁止本地路径、SSH 和 `file:` 传输。克隆会先关闭 LFS 自动下载，检查 `.lfsconfig` 后才拉取 LFS 内容。

Git 默认使用环境代理、Windows/macOS 静态系统代理或全局 Git 的 `http.proxy` 值。用户也可选择直连或不含凭据的自定义 HTTP/HTTPS/SOCKS5 地址。配置只影响 XAim 的仓库下载进程，不改写用户全局 Git 配置；PAC 和代理认证尚不支持。

连接失败后保留实际退出码和原因，提示检查 Git 网络设置；修改后可使用“重试本次任务”发起同目标的新一轮。任务总时限仍包括等待授权的时间，超过时限或退出应用不会执行旧请求。

仓库操作逐阶段记录目标检查、下载、LFS 检查、仓库核对、子模块检查与完整目录交付。工具结果的 `authorizationWaitMs` 只表示等待批准；`executionDurationMs` 与显示的执行耗时不包含这段等待。`authorizationGranted=true` 的 IO 故障不应解释为用户未批准。可恢复的克隆错误返回模型，使其能够选择尚不存在的子目录；程序不会自动删除非空目录或替换现有仓库。

Windows 命令以挂起状态创建，加入负责清理子进程的 Job Object 后才恢复执行，避免短命进程先退出与子进程逃逸。目录交付遇到 Windows 短暂句柄占用时最多重试两秒，每次仍使用原子“不覆盖现有目标”操作；取消、任务时限与目标被其他进程创建均停止交付。

原生工具流程在每次实际开发操作与自动检查前校验权限。非工具模型的兼容补丁流程使用相同的权限检查器进行最终验证，不再通过候选评分器未经授权执行脚本；它仍不具备克隆、依赖安装与服务管理能力。开发评测等无桌面交互的调用方保持显式授权配置。
